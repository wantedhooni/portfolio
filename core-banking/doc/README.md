## 🧱 모든 도메인에 공통으로 흐르는 개념

도메인 문서를 읽기 전에 알아두면 좋은 **횡단(cross-cutting) 규칙**입니다.

### 1. 리치 도메인 모델 (Rich Domain Model)
엔티티는 단순한 데이터 그릇(getter/setter 덩어리)이 아니라 **스스로 비즈니스 규칙을 강제**합니다.

- **public 생성자 금지** — 생성은 `Account.open(...)`, `JournalEntry.draft(...)` 같은 **정적 팩토리 메서드**로만.
- 팩토리·행위 메서드 안에서 **불변식(invariant)을 검증**합니다.
  예) `AccountTx`의 금액은 반드시 양수, `JournalLine`은 차변·대변 중 정확히 한쪽만 양수.
- 상태 변경은 의미 있는 도메인 행위로만. `setStatus(CLOSED)` 대신 `account.close()`.

### 2. 멱등성 키 (`referenceId`)
돈이 움직이는 거래는 **재시도/중복 호출에도 한 번만 반영**되어야 합니다.
주문·이체·환전·보험료 납부 등은 `reference_id`(또는 `order_no`, `conversion_number`)에
**유니크 제약**을 걸어, 같은 키로 두 번 들어오면 두 번째는 무시되도록 설계합니다.

> 현업에서 "한 번의 클릭 → 두 번 출금" 같은 사고를 막는 가장 기본적인 안전장치.

### 3. 낙관적 락 (`@Version`)
잔고·수량처럼 **동시 갱신 충돌 가능성이 높은 엔티티**(`Account`, `StockPosition`,
`PositionLot`, `StockOrder`, `JournalEntry`, `FxConversion`, `InsurancePolicy` 등)에는
`@Version` 컬럼을 두어 충돌을 감지합니다. 충돌 시 `OptimisticLockException` →
서비스 계층에서 **재시도**합니다. (행을 잠그지 않으므로 처리량에 유리)

### 4. 시각 타입 규칙
- `Instant` : 거래 발생/체결 시각처럼 **타임존 독립적인 한 시점**. (분산 환경 기준)
- `LocalDate` : 회계 일자·만기일·정산 기준일처럼 **달력상의 날짜**.
- 모든 엔티티는 `BaseEntity`를 상속해 `createdAt` / `updatedAt`(JPA Auditing)을 자동 기록합니다.

### 5. 금액 표현
모든 금액·수량은 **`BigDecimal`**(부동소수점 금지). 통화별 소수 자릿수가 다르므로
(`KRW`=0, `USD`=2, `BHD`=3) 통화 메타데이터를 함께 관리합니다.

### 6. 거래의 단일 진실 공급원(SoT) — 원장과 거래내역의 분리
- **`AccountTx`** : 계좌 잔고를 움직인 **거래 명세**(고객 관점).
- **`JournalEntry`(원장)** : 회계적으로 차변/대변이 일치하는 **복식부기 기록**(회계 관점).
- 하나의 비즈니스 이벤트(예: 주식 매수)는 `AccountTx`로 잔고를 바꾸고,
  배치/이벤트를 통해 `JournalEntry`로 **원장에 전기(posting)** 됩니다.

## 🔁 도메인 간 상호작용 한눈에 보기

```
[사용자]──개설──▶[계좌]
                  │
   ┌──────────────┼───────────────┬──────────────┐
   ▼              ▼               ▼              ▼
[주식 주문]    [외환 환전]      [보험료 납부]   [이체/입출금]
   │ 체결         │ 환전           │ 자동이체        │
   ▼              ▼               ▼              ▼
       ┌─────────[ AccountTx (거래내역) ]─────────┐
       │                                          │
       ▼                                          ▼
 [청구/정산 Settlement]                   [총계정원장 JournalEntry]
                                                  ▲
[PG 결제]──정산배치──────────────────────────────┘
```

핵심 원칙: **모든 돈의 움직임은 결국 `AccountTx`를 거치고, 회계적으로는 `JournalEntry`(복식부기)로 귀결된다.**
