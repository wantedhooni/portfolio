# Spring Boot 4 + JPA Entity + QueryDSL JPA + Spring Batch Demo

`orders` 30만 건을 기준으로 일별 상품 매출 통계를 생성하는 데모 프로젝트다.

이번 버전은 기존의 수동 `RelationalPathBase` Q클래스를 제거하고, **JPA Entity 기반 QueryDSL Q클래스**가 annotation processor로 생성되도록 수정한 구조다.

## 기술 스택

- Java 21
- Spring Boot 4.0.6
- Spring Data JPA
- Spring Batch / Spring Batch JDBC
- QueryDSL JPA 5.1.0 `jakarta`
- H2 In-Memory Database
- Gradle

## 핵심 변경점

### 이전 구조

```text
QueryDSL SQL
수동 작성 QOrders / QDailyProductSalesStat
SQLQueryFactory
insert(...).select(...)
```

### 현재 구조

```text
JPA Entity
QueryDSL JPA annotation processor 생성 Q객체
JPAQueryFactory
QueryDSL GROUP BY 조회
EntityManager persist batch insert
Spring Batch Tasklet 실행
```

주의할 점은 JPA QueryDSL은 `INSERT INTO ... SELECT ...`를 직접 표현하는 도구가 아니다. 따라서 이 프로젝트는 다음 흐름으로 구현한다.

```text
1. QueryDSL JPA로 GROUP BY 집계 조회
2. DTO로 결과 수신
3. JPA Entity로 변환
4. EntityManager persist + flush/clear로 batch insert
```

## 데모 데이터 생성 SQL

```text
src/main/resources/data.sql
```

H2 `SYSTEM_RANGE`로 30만 건을 생성한다.

```sql
INSERT INTO orders (id, ordered_at, product_id, amount, status)
SELECT
    x AS id,
    DATEADD('SECOND', MOD(x, 864000), TIMESTAMP '2026-05-01 00:00:00') AS ordered_at,
    CAST(MOD(x, 1000) + 1 AS BIGINT) AS product_id,
    CAST((MOD(x * 37, 200000) + 1000) / 10.0 AS NUMERIC(19, 2)) AS amount,
    CASE
        WHEN MOD(x, 20) = 0 THEN 'CANCELLED'
        ELSE 'PAID'
    END AS status
FROM SYSTEM_RANGE(1, 300000);
```

30만 개 literal insert를 나열하지 않고 DB 내부에서 생성한다.

## JPA Entity

```text

src/main/java/com/example/querydslsqldemo/entity/DailyProductSalesStat.java
```

`OrderEntity`는 `orders` 테이블에 매핑한다.

```java
@Entity
@Table(name = "orders")
public class OrderEntity {
    @Id
    private Long id;

    @Column(name = "ordered_at", nullable = false)
    private LocalDateTime orderedAt;

    @Column(name = "product_id", nullable = false)
    private Long productId;

    @Column(name = "amount", nullable = false, precision = 19, scale = 2)
    private BigDecimal amount;

    @Column(name = "status", nullable = false, length = 20)
    private String status;
}
```

## QueryDSL Q객체 생성 설정

`build.gradle`에서 QueryDSL JPA annotation processor를 사용한다.

```gradle
implementation "com.querydsl:querydsl-jpa:${querydslVersion}:jakarta"
annotationProcessor "com.querydsl:querydsl-apt:${querydslVersion}:jakarta"
annotationProcessor 'jakarta.persistence:jakarta.persistence-api'
annotationProcessor 'jakarta.annotation:jakarta.annotation-api'
```

빌드하면 다음 경로에 Q객체가 생성된다.

```text
build/generated/sources/annotationProcessor/java/main
```

예상 생성 Q클래스:

```text
com.example.querydslsqldemo.entity.QOrderEntity
com.example.querydslsqldemo.entity.QDailyProductSalesStat
```

## 핵심 QueryDSL JPA 코드

파일:

```text
src/main/java/com/example/querydslsqldemo/repository/DailyProductSalesStatJpaQueryRepository.java
```

```java
return queryFactory
        .select(Projections.constructor(
                DailyProductSalesStatRow.class,
                Expressions.constant(targetDate),
                order.productId,
                order.amount.sum(),
                order.id.count()
        ))
        .from(order)
        .where(
                order.orderedAt.goe(from),
                order.orderedAt.lt(to),
                order.status.eq("PAID")
        )
        .groupBy(order.productId)
        .fetch();
```

저장은 JPA `EntityManager`로 batch persist한다.

```java
for (int i = 0; i < stats.size(); i++) {
    entityManager.persist(stats.get(i));

    if ((i + 1) % PERSIST_BATCH_SIZE == 0) {
        entityManager.flush();
        entityManager.clear();
    }
}
```

## 설계상 주의점

JPA QueryDSL 기반이므로 긴 Native SQL 문자열은 제거된다. 다만 `INSERT SELECT`는 JPA QueryDSL의 범위가 아니므로, 성능상 DB 내부 `INSERT SELECT`가 필요한 운영 배치라면 QueryDSL SQL 또는 jOOQ가 더 적합하다.

이 데모는 사용자가 요청한 기준에 맞춰 다음을 우선한다.

```text
JPA 객체 기반
Q객체 annotation processor 생성
테이블 생성 SQL 포함
Spring Batch 실행 경로 포함
Native Query 문자열 제거
```
